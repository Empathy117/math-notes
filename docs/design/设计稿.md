## 0. 调研对原设想的修正

先列会改变设计的事实，再进入设计。

1. **org-mode 的快速预览不是现成组件。** 新版 org-latex-preview 没进任何正式版 Org，只在 tecosaur 的 dev 分支。它快的原因是摊销：一个 buffer 的所有片段进同一个 .tex 文件、preamble 用 mylatexformat 预编译成 .fmt、结果按 sha1 缓存、后台异步。这套手法可以搬到我们将来的"服务端真 TeX"层，但它本身不能嵌进网页。（latex_rendering_engines Q1）
2. **结构化编辑器只有一个活着的开源选择。** MathLive 0.110.0 是 2026 年唯一"活跃维护 + MIT + 完整结构化编辑"的 Web 方案；MathQuill 上游 2025 年 6 月起停更，npm 停在 2022。所以 R3 不需要自研，但也几乎没有备胎，要为它锁版本、写回归、加硬适配层。（structural_math_editors Q6）
3. **模糊输入转公式不是"调一次 API"。** 口述数学转 LaTeX 这类任务上，通用大模型的字符错误率约 30% 到 40%；微调过的小模型能追平。所以 AI 层必须带一条宿主侧的校验、重试、歧义暴露流水线。（ai_layer Q1）
4. **各渲染器的错误信号不一致。** KaTeX 最严格且给出错误位置；MathJax 4 对未定义宏默认不报错而是染红；MathLive 的 validateLatex 漏报缺右括号。结论：语法裁判用 KaTeX，构造清点用 AST 解析器，可编辑性判断用 MathLive。（ai_layer Q4）
5. **"可渲染"和"可结构化编辑"是两个集合。** amscd 的 CD 环境 KaTeX 能渲染但 MathLive 不认识；MathLive 输出的 `\differentialD` KaTeX 反而不认识。能力注册表必须把两者分开标。（ai_layer Q4、formula_representation_formats Q4）
6. **树格式回吐 LaTeX 都会改写字面。** MathJSON、MathML、Typst、MathLive 的 atom 树都是如此。要做到"用户写什么就存什么"，真源只能是 LaTeX 字符串，且只有用户真的做了结构编辑才允许用编辑器的序列化结果覆盖它。（formula_representation_formats Q1、Q4）

## 1. 需求编号

| 编号 | 需求 |
|---|---|
| R1 | 底部输入框接受模糊描述、不精准公式、听写文本；AI 只产公式，实时渲染插入笔记 |
| R2 | 正文是普通文字笔记，需要时插入行内或块级公式 |
| R3 | 渲染后的公式可结构化点击编辑（点 `lim` 下标的 0 直接改），默认不塌缩为源码 |
| R4 | 可切换到源码模式 |
| R5 | 选中公式的一部分加批注，让 AI 修改 |
| R6 | 选中一段文字，一键变成公式 |
| R7 | 语音输入由系统听写提供，组件只处理文本 |
| R8 | 可复用到学习系统：框架无关、可导出 Markdown 和 LaTeX、将来接 Anki 等 |
| R9 | 能力边界可优化不锁死：同一公式不同写法可接受；超出支持范围时明确告知"超出边界、可后续添加"，不让用户误以为 AI 出错 |

**v1 非目标**：多人协同、手写识别、图片 OCR、整篇文档排版导出 PDF、语音识别本身。

## 2. 总体架构

核心思想：**不要求一种表示同时适合存储、显示、编辑和 AI 理解。** LaTeX 负责保存数学，ProseMirror 负责保存文档结构，KaTeX 负责显示，MathLive 负责编辑，一份线性文本投影负责给 AI 读。每一层只在自己的边界内有改写字面的权力。

```
┌──────────────────────────────────────────────────────────────────────┐
│ L5 宿主集成层   web component（暂名 <math-notes>）或 Tiptap 扩展集         │
│     props: resolveMath, capabilities, macros, value                    │
│     events: change, math-inserted, boundary-hit                        │
├──────────────────────────────────────────────────────────────────────┤
│ L4 能力注册表 + 边界反馈 + 安全门（贯穿 L1 到 L3）                          │
├──────────────────┬───────────────────────┬───────────────────────────┤
│ L1 渲染层          │ L2 结构化编辑层          │ L3 AI 层                    │
│  Tier0 缓存        │  MathLive 会话式挂载     │  输入意图分类 → 注入函数        │
│  Tier1 KaTeX      │  经硬适配层接入          │  结构化输出                   │
│  Tier2 MathJax    │  块级/行内就地，弹层降级   │  同步门 → 异步检查 → 分类       │
│  Tier3 图表（后续） │  源码模式切换            │  AI 文档投影（给模型读整篇）     │
├──────────────────┴───────────────────────┴───────────────────────────┤
│ L0 文档模型   ProseMirror 文档树；公式 = inline / block atom 节点            │
│     节点只存事实：latex、display、annotations、provenance                  │
│     派生分析（features、后端选择、语义树）放插件状态与缓存，不进文档            │
└──────────────────────────────────────────────────────────────────────┘
```

R1 的主数据流：

```
输入框文本
  → 输入意图分类（D6）
      ├─ 显式 LaTeX 意图 → 安全门 → KaTeX 校验 → 直接插入，不调 AI
      ├─ 灰区（sin x、lim x->0 …）→ AI，附"可能是不精准公式"的提示
      └─ 自然语言 / 听写 → AI
  → resolveMath({kind:'generate'}) → MathResult
  → 安全门（D14）
  → 同步门：AST 清点 → 注册表 → KaTeX 严格解析（D6）
      ├─ 通过 → 插入节点，渲染；异步检查在后台继续
      ├─ 歧义 → 插入默认解释，节点旁显示"按 … 理解 · 改为 …"
      ├─ 语法错 → 自动修一次，仍错则带位置回传模型重试一次
      └─ 越界 → 不插公式，显示边界提示，保留原文（D7）
```

## 3. 决策点

### D1 公式的真源格式

| 候选 | 说明 |
|---|---|
| A. LaTeX 字符串（不带定界符） | 生态唯一通吃的格式 |
| B. Typst 数学源 | 语法贴近自然打字，编译器诊断结构化 |
| C. MathJSON 树 | 语义清晰，可求值 |
| D. Presentation MathML | 浏览器原生渲染 |

**倾向：A。** 三层结构：LaTeX 字符串持久化；MathLive 的 atom 树只在编辑会话中存在；MathJSON 由 Compute Engine 按需派生（`form: 'raw'` 用于保持字面结构的局部操作，canonical 形式用于判等和去重）；MathML 只作导出物，并在 `<annotation>` 里带上 LaTeX 源。

依据：
- Anki、Obsidian、Notion、Jupyter、GitHub、pandoc 全部原生消费 LaTeX 字符串，R8 的导出零转换。（formula_representation_formats Q1、Q6）
- 所有树格式回吐都改写字面（见第 0 节第 6 条）。MathLive 已在 master 分支计划拆掉 Compute Engine 依赖，两份笔记对 0.110.0 是否已经移除有分歧，npm 依赖证据支持"尚未移除"；拆分后正好对应"持久值 / 编辑树 / 语义树"三层。（formula_representation_formats Q4；报告的矛盾表）
- MathJSON 官方明言不能替代 LaTeX 或 MathML 做视觉表示。

**字面不变量，如实表述**：
- 结构编辑之前，公式字节保持用户或 AI 写下的原样。
- 一旦用户在 MathLive 里做了结构编辑，允许用 `getValue('latex')` 的序列化结果覆盖原文。此时保证的是**语义与结构范围不越界**，不保证未被选中的区域字节级拼写完全不变，因为 MathLive 的选区 offset 不是源码字符 offset，且它会把被编辑子树重写为紧凑形式。围绕"未选中区域字节不变"写补丁是做不到的，不承诺。
- `serialize(parse(s)) === s` 只作为**序列化漂移探测器**用在升级回归里（典型公式集在新旧 MathLive 上各跑一遍 parse、edit、serialize，比对 diff 是否超出允许的规范化范围），不作为保存时的正确性检查，也不向用户逐条弹"编辑后会改写拼写"的提示。

**Typst 的位置**：不做真源。它的三个优点（输入贴近自然打字、图表覆盖面、错误可机读）对我们的价值有限，因为自然语言输入由 AI 处理，而代价明确：编译器 WASM 解包约 28 MB、pre-1.0 有破坏性变更、没有 Typst 版的结构化编辑器、与学习系统生态互通要经 tex2typst 有损转换。保留两个位置：Tier 3 图表渲染候选之一，以及将来若做"线性输入语法"时的参考。（typst_alternative Q3、Q5、Q9）

### D2 正文编辑器路线

| 候选 | 代表 | 公式如何存在 |
|---|---|---|
| A. 结构化文档树：ProseMirror（经 Tiptap core） | Notion、Milkdown、Tiptap | inline / block atom 节点，LaTeX 存属性 |
| B. 源码 + 装饰：CodeMirror 6 | Obsidian、Overleaf | Markdown 纯文本，公式是 `Decoration.replace` 的 widget |
| C. Lexical | Meta 系产品 | DecoratorNode |
| D. 现成整包 | Milkdown Crepe、BlockSuite | 弹层里编辑源码 |

**决定：A，2026-09-26 定案。** 宿主是 React + Vite，因此用 Tiptap core 加 `@tiptap/react` 做演示与宿主绑定，核心扩展保持纯 JS。

依据：
- R3 的"点击不塌缩"在 A 类是默认行为；B 类默认塌缩为源码，Overleaf 和 Latex Suite 只能用悬浮预览补偿。（note_editor_math_ux_architecture Q1）
- B 类要"在投影里再开一个编辑器"，与 `atomicRanges` 冲突，焦点交接要自理。（note_editor Q2）
- C 仍是 0.x，偏 React；D 的交互已被定型为弹层源码编辑，改不了。
- Tiptap Mathematics 扩展 2025 年 6 月起 MIT 开源，节点 schema 和命令可以直接作为起点，把它的 `onClick` 换成我们的编辑会话。
- ProseMirror 的 JSON 难读**不影响 AI**：AI 看到的是另一份投影（D13），带稳定节点 ID 的线性文本，反而比裸 Markdown 更容易精确指出问题和回写修改。

代价与对策：
- Markdown 往返要自理：固定用 remark-math 方言（`$…$`、`$$…$$`），导出时按目标换定界符。
- 节点两侧光标：按 ProseMirror 维护者的建议，在节点 DOM 两侧放无 `src` 的 `<img>` 作缓冲位。（note_editor Q3）
- 撤销：编辑会话内不写宿主历史，退出时一次提交。
- 协同：LaTeX 存属性意味着 Yjs 下整条公式 last-writer-wins。v1 不接 Yjs；若将来要多人协同，再评估存节点文本。

**何时应选 B**：如果你希望"Markdown 文件就是文档本体"，像 Obsidian 那样文件即真源、外部工具随时能改。那时 B 的复制、撤销、协同、往返几乎免费，但公式只能在弹层里结构化编辑，且要处理 widget 焦点和 IME 邻接问题（CodeMirror 6 在 2026 年 7 月才修了一批）。

**Typora 式 Markdown（2026-09-26）**：文档仍是结构化的，Markdown 标记只作为装饰显示在光标所在处：标题前的 `## `、引用的 `> `、粗体两侧的 `**`、斜体 `*`、删除线 `~~`、行内代码的反引号、链接的 `[…](网址)`、代码块的围栏，光标离开就隐藏，编辑器失去焦点时全部隐藏（`tiptap/markdown-reveal.ts`）。删除标记的效果与 Typora 一致：在标题文字开头退格，等于删掉 # 后面的空格，标题变成以 `##` 开头的普通段落，再打一个空格又成为标题，所以改 # 的个数就是改级别；在粗体等格式开头退格，去掉这层格式。输入沿用 StarterKit 的 Markdown 输入规则，另外打开了链接的 `[文字](网址)` 输入与粘贴；链接改为 Cmd/Ctrl+点击才打开。选择装饰而不是把标记真写进文档，是为了不让光标移动产生文档改动：撤销历史、一键转公式的文本投影、复制粘贴都只看到内容本身。

已定案，见第 7 节。

### D3 公式节点的交互模型

**目标交互：块级公式就地编辑，行内公式也就地编辑。** 产品的核心体验是"公式和文字像同一种东西一样直接编辑"，行内公式一点就弹层会让产品退回传统 Markdown 编辑器的味道。已知的工程风险不足以在开工前判死刑，但足以要求一个有明确门槛的 spike。

**决定（2026-09-26）**：接受"目标就地、三档并测、按门槛取最高档"的策略。

**S1 实测结果（2026-09-26，详见 `docs/spikes/S1 行内编辑三档实测.md`）**：三档的键盘、鼠标、撤销门槛全部通过；档 1 真就地只有一项布局差异，含 `\lim` 的公式进入编辑时行高 +5.5px，来源是 MathLive 在行内样式下不把 `\lim` 的 limits 放到旁边。段首公式拖选失效的老问题已解决：NodeView 外层 `contenteditable=true`、静态内核 `contenteditable=false`、两侧 1px 不可拖拽的 `<img>` 缓冲。据此 **MVP 默认取档 1 真就地，overlay 保留为设置项，弹层作为不可结构化编辑节点的降级路径**。另一个影响设计的发现：MathLive 宿主继承 `contenteditable=false` 会拒收键盘输入，所以字段必须挂在可编辑的外层内。**后续修复**：`\lim` 的行高差异已消除（适配层补 `\displaylimits` 垫片，字段字号与行高对齐 KaTeX），三档布局门槛都收紧到 0.5px；空格、回车留在公式里，方向键走到头才离开，见 S1 文档末节。

**降级策略**：S1 里同时实现三种行内方案，按验收门槛取通过的最高档，进不了 MVP 的留在后续版本：

| 档 | 方案 | 机制 | 优点 | 风险 |
|---|---|---|---|---|
| 1 | 真就地：NodeView 内嵌 `<math-field>` | inline atom 节点，点击时把静态渲染替换为 `<math-field>`；两侧放无 `src` 的 `<img>` 作光标缓冲 | 视觉与交互完全一体 | 两个编辑器争抢光标与选区；Chromium 中行内 `<math-field>` 让 ArrowDown 跳到文末（MathLive #2939，open）；多字段焦点闪烁（#2579）；静态与编辑态度量不同导致整段重排 |
| 2 | 伪就地：overlay | 文档里仍是 atom 节点；点击时把 KaTeX 节点设为 `visibility: hidden`，在 portal 里用 `position: absolute` 把 `<math-field>` 精确盖在原位（`getBoundingClientRect()` 对齐 left、top、baseline），宽度变化时同步撑开隐藏节点 | 避开嵌套 contenteditable；ProseMirror 的选区模型不受干扰；用户看起来就是原地编辑 | 基线对齐要测；滚动与窗口缩放要重定位；编辑中拖选无法跨出到正文 |
| 3 | 锚定弹层 | 公式保持渲染态，点击后在其下方弹出 `<math-field>`，光标用 `getOffsetFromPoint` 直达点击处 | 工程最稳，Notion、RemNote 的成熟模式 | 多一步，产品感下降 |

块级公式直接用档 1，它独占一行，没有与正文光标争抢的问题。（structural_math_editors Q2、Q7；note_editor Q3）

会话规则（三档共用）：
- 非编辑态只放 KaTeX 静态渲染，不常驻 `<math-field>`。
- 进入：点击时挂载 `<math-field>`，载入 `latex`，光标按点击坐标定位。
- 键盘进入：方向键移到公式上即打开编辑，光标落在进入的那一侧，这是 Notion 与 RemNote 的做法；与下面的 `move-out` 配合，形成双向键盘导航。
- 事件隔离：NodeView 的 `stopEvent` 对 `composedPath()` 含该字段的事件返回 true；`ignoreMutation` 返回 true。
- 退出：监听 `move-out` 事件，按 `detail.direction` 把外层光标放到节点前或后并 `view.focus()`；Esc 或失焦时提交。
- 提交：会话内 `input` 事件只更新预览，退出时一次 `setNodeMarkup`，宿主撤销把整次编辑视为一步；会话内逐键撤销交给 MathLive 自己的历史。

S1 的验收门槛见第 5 节。

### D4 渲染分层与缓存

| 层 | 引擎 | 触发 | 体积（gzip） | 作用 |
|---|---|---|---|---|
| Tier 0 | 缓存 | 总是 | 无 | 键 = hash(latex, display, 宏表版本, 各引擎版本, 注册表版本, 主题)，借自 org-latex-preview |
| Tier 1 | KaTeX，`throwOnError: true` | 默认 | 约 76 KB + 按需字体 | 同步、快、错误带位置；`strict` 回调收集不规范写法 |
| Tier 2 | MathJax 4，懒加载 | Tier 1 报"未知命令或环境"且构造在 MathJax 支持集内（physics、bussproofs、`\label`、`multline` 等） | 约 281 KB | 覆盖面最广；必须去掉 `noundefined` 才能判失败；在 Worker 中运行并带超时 |
| Tier 3 | 服务端真 TeX（首选，学习系统有后端）；TikZJax 作无后端场景的备选 | 命中 `tikzcd`、`tikzpicture`、`xymatrix`、`chemfig` 等 | 待测 | v1 不实现，只识别、提示、保留源码、占位。服务端配方照搬 org-latex-preview：批处理进 preview 页、mylatexformat .fmt、auctex 伪错误标记切分逐片段错误、dvisvgm 出 SVG、sha1 缓存；沙箱要求见 D14。Typst 不作为主路线，真源本来就是 LaTeX，引入它等于多一套图表语义 |

Temml 作为 Tier 1 的备选：只有约 50 KB，输出 MathML 交给浏览器排版，2026 年所有主流浏览器都支持 MathML Core。风险是跨浏览器渲染质量仍有差异，而 KaTeX 用字体度量表排版，各端像素一致。**倾向 KaTeX**，Temml 留作可切换的渲染后端。（latex_rendering_engines Q2、Q4；formula_representation_formats Q7）

静态层与编辑层的引擎问题：非编辑态用 KaTeX、编辑态用 MathLive，两者排版细节不同，进入编辑时可能有细微的布局跳动，对行内公式尤其敏感。因为 MathLive 无论如何都要加载，另一个选项是可结构化编辑的节点静态渲染也直接用 MathLive 的静态输出，外观完全一致，只把不可编辑的节点交给 KaTeX。代价是两套渲染并存、缓存键要带引擎标识。这一点放进 S1 的布局门槛一起测。

渲染缓存（SVG、MathML、渲染后的 HTML）放 LRU 与 IndexedDB，键同 Tier 0，**不进文档**。导出时按需从缓存取回退渲染写入导出物（D11）。

性能手法：widget 复用（`eq()` 比较源码与模式）、异步或防抖渲染、缓存测得高度、拖选期间暂停重算。（note_editor Q7）

需实测：单公式渲染延迟（笔记里没有 2024 年后的独立基准）；TikZJax 首次加载体积与单图编译时间（笔记里没有任何数字）。

### D5 结构化编辑器选型与适配层

**决定（2026-09-26）：MathLive，最低版本 0.110.0，通过一层硬适配接入；适配层加锁版本加升级回归作为对单点依赖的全部对策。**

- 0.110.0 修了 `\text{}` 里的 XSS，渲染 AI 输出必须用这个版本以上。
- 满足 R3 与 R5 的 API 都是现成的：`selection`、`getValue(start, end, 'latex')` 取局部 LaTeX、`insert(latex, {insertionMode: 'replaceSelection'})` 替换选区、`getOffsetFromPoint` 定位点击、`validateLatex(latex, {macros})` 校验并返回 14 种结构化错误码、`readOnly` 和 `\placeholder[id]{}` 做填空。（structural_math_editors Q2）
- 输入快捷：MathLive 的 inline shortcuts 在字段内把 `sqrt`、`int`、`->` 边打边变成符号，编辑会话内的"不精准公式"很多不用过 AI。

**适配层是架构原则，不是风险缓解措施**。MathLive 单人维护、半年一个破坏性大版本、master 计划移除 `expression` 与 `"math-json"`、行内 ArrowDown 问题仍 open，这些说明它是"需要锁版本和回归测试的活跃依赖"。所有 MathLive 的 API 与类型只允许出现在 `mathlive-adapter/` 目录内；NodeView、AI 层、文档模型只认下面的接口。将来替换或自研编辑器，改的是适配层而不是系统。

```ts
interface StructuredMathEditor {
  mount(host: HTMLElement, latex: string, opts: { macros: MacroTable; readOnly?: boolean }): void;
  unmount(): void;
  getValue(): string;
  setValue(latex: string, opts?: { silent?: boolean }): void;
  getSelection(): { start: number; end: number; latex: string; before: string; after: string };
  replaceSelection(latex: string): void;
  positionFromPoint(x: number, y: number): number;
  focusAt(position: number): void;
  validate(latex: string, macros: MacroTable): ValidationIssue[];
  on(event: 'change' | 'commit' | 'moveOut' | 'selectionChange', handler: (e: EditorEvent) => void): () => void;
}
```

风险与对策：
- 中文输入法与 `insert()` 的冲突（#3058）：该 issue 明确写了在微软注音的字母数字模式下同样复现，根因是 `onCompositionStart` 无条件删除当前选区，而且程序化输入绕过 IME、自动化测试无法重现。所以"把 insert 延后到 composition 结束"不一定能修，只能靠 D12 的 IME 矩阵实测，必要时在适配层做平台特判。
- 序列化漂移：按 D1 的规则，只在用户改动后写回；升级时跑漂移回归。
- 供应链：npm 上有若干第三方 fork，其中一个版本号高于官方最新版却指向上游仓库。只用官方 `mathlive` 包，锁定次版本。（structural_math_editors Q6）

### D6 AI 层契约

**输入意图分类**（快路径的正确判据）。"KaTeX 能解析"不等于"用户在输入 LaTeX"：`sin x` 在 KaTeX 里是四个变量 s、i、n、x 的乘积，`x的平方` 带警告也能通过。快路径要问的是"我们是否高度确信用户在输入字面 LaTeX"：

```
显式 LaTeX 意图 → 直接插入（仍过安全门与 KaTeX 校验）
  · 在源码模式下输入
  · 含反斜杠命令（\frac、\sin、\int …）
  · 粘贴内容带 $…$ 或 \[…\] 定界符
  · 受限表达式：只含单字母变量、数字、运算符、^ _ {} ()；
    不含连续两个以上字母的裸单词、不含中文、不含 ->、=>、lim、int、sqrt 一类口语缩写
灰区 → AI，附提示"可能是不精准公式"
  · sin x、lim x->0 sin x/x、e^x + abc
自然语言与听写 → AI
```

例：`x^2+y^2=1` 直接插入；`\sin x` 直接插入；`sin x` 走 AI。分类器的准确性是 S0 的内容，它比模型准确率更靠前，因为请求只有真的进了模型，模型准确率才有意义。

**注入函数**（组件不绑定任何供应商，宿主传入）：

```ts
type MathRequest =
  | { kind: 'generate'; input: string; context: MathContext; retry?: RetryInfo }   // R1：输入框
  | { kind: 'convert';  input: string; context: MathContext; retry?: RetryInfo }   // R6：选中文字
  | MathEditRequest;                                                               // R5：见 D8

// 同步门的一次重问：上一次的 latex 和渲染器报错；latex 为空表示上一次的输出本身不可用（截断、JSON 损坏）
type RetryInfo = { latex: string; message: string; position?: number };

interface MathContext {
  surroundingText?: string;          // 由 AI 文档投影（D13）截取的光标附近文本
  notation?: string[];               // 本页已出现的记号习惯，例如 "\mathrm{d}"、"\vec"
  macros?: Record<string, string>;   // 文档级宏表
  capabilities: CapabilitySnapshot;  // 注册表版本 + 支持的 features 摘要，供模型判断 features
  locale: 'zh-CN' | 'en';
}

interface MathResult {
  status: 'ok' | 'ambiguous' | 'unsupported' | 'not_math';
  interpretation: string;            // 一句话复述理解，用用户语言；放在 latex 之前
  latex: string;                     // 不带定界符
  alternatives: { latex: string; interpretation: string }[];   // 含义不同的其他读法；非空当且仅当 status 为 ambiguous
  notations: { latex: string; interpretation: string }[];      // 同一含义的其他写法（\mathbf{a} 与 \vec{a}），不算歧义
  features?: string[];               // 用到或需要的功能，例如 ["tikz-cd"]；只是提示，宿主复核
  confidence: 'high' | 'medium' | 'low';
  consistency?: { kind: 'numeric' | 'none'; expected?: string };   // 见下文，不叫核验
  notes?: string;
}
```

设计要点：
- **只输出公式靠结构化输出，不靠提示词。** 2026 年 Anthropic、OpenAI、Gemini 都支持按 JSON Schema 约束解码；宿主只取 `latex` 字段。字段全部用字符串和 enum，兼容各家对数值约束的限制。`interpretation` 放在 `latex` 前面，给受约束解码留一个极短的"先想后写"槽位。（ai_layer Q1）
- **不支持结构化输出的模型**（部分本地模型）：要求只输出一行 LaTeX，用换行作 stop sequence，宿主剥离 `$…$`、`\[…\]` 和代码围栏。无论哪种方式，渲染器校验是最终裁决。
- **触发方式**：显式触发，回车或听写结束后按一次快捷键；不做边打边转，避免请求风暴和半句话被误解析。
- **记号一致性**：`notation` 里附带本页已经出现的写法，例如微分用 `\mathrm{d}` 还是 `d`、向量用 `\vec` 还是 `\mathbf`，让模型沿用同一套。
- **不做确定性预览**：不用 MathLive 的 AsciiMath 转换或 Compute Engine 宽松解析做"先显示个东西"，实测它们把 `lim_(x->0) sin(x)/x` 解析成作用域错误的结果，预览会误导。（ai_layer Q2）
- **溯源**：每次 AI 生成把原始输入、模型标识、时间存进节点的 `provenance`。

**校验流水线，两阶段**。研究笔记测得单条公式各校验合计不到 1 毫秒，但那是 5 条小公式的实测，不是设计保证；复杂矩阵、宏展开、Compute Engine 求值都没有理由满足固定预算。所以拆成：

```
同步门（预算：不阻塞一帧；超预算即转异步并先插入占位）
  安全门（D14）
  → 预处理：剥定界符、去 \label / \tag、剥代码围栏
  → AST 清点（unified-latex）：features、宏、环境、深度、节点数
  → 查能力注册表（D7）
  → KaTeX 严格解析：ParseError.position / length → 语法类错误
  → 决定：插入 / 歧义 chip / 自动修后重试 / 边界提示

异步检查（Web Worker，带超时与预算，不阻塞插入，结果以装饰形式补到节点上）
  MathLive validateLatex({macros}) → 可编辑性（editBackend）
  Compute Engine parse / evaluate → 一致性检查
  Tier 2 渲染（需要时）

分类处理：
  syntax                → 自动修一次（补括号、去 $）；仍错则把 rawMessage + position 回传模型重试一次
  unsupported-construct → 边界提示，不重试
  renderer-gap          → 升级 Tier 2 渲染，节点标"不可结构编辑"
  semantic-warning      → 低打扰提示或 alternatives（例如 \sin x/x 会被读成 sin(1)）
```
（ai_layer Q4、Q6）

**重试已落地（S4）**：`resolveWithRetry`（`packages/core/src/ai/retry.ts`）实现"重问一次"。KaTeX 拒绝时，把被拒的 latex 和报错一起回传；输出本身不可用时（被 max_tokens 截断，或 JSON 坏到修不好，统一抛 `ModelOutputError`），带一句说明重问。说明不能省：temperature 0 下，原样重发会拿回同一份坏输出。区分 syntax 和 unsupported-construct 要等 S3 的注册表，目前所有拒绝都重问一次。alternatives 和 notations 里 KaTeX 渲染不了的项直接丢掉。解析层会修补模型常犯的 JSON 小错：未转义的 LaTeX 反斜杠、尾逗号、漏掉的右括号。它还会还原被合法 JSON 转义吞掉的命令，例如 `\frac` 被解析成"换页符 + rac"的情况。明显是 JSON 但修不好的文本一律报错，绝不当作公式插入。`max_tokens` 默认值 1200：8 个麦克斯韦方程就要用掉约 400 个 token，而被截断的回答重问一次，通常还是一样长。

**宿主的语义检查（S4）**：上表里的 semantic-warning 已部分落地，即 `offerKnownReadings`（`packages/core/src/ai/semantic.ts`），在 `resolveWithRetry` 里统一调用。有两类歧义，提示词里加了规则和示例，模型仍然标得不稳定，所以改由宿主确定性地补上另一种读法。第一类是手敲的 `sinx/x`、`ln t/t`（函数名后没加括号就接斜杠），补上 `\sin\left(\frac{x}{x}\right)`；第二类是口述的"根号下 A 加/减 B"，补上 `\sqrt{A}+B`。`sin(x)/x`、`sin x/(x+1)`、口述的 over、不带"下"的"根号 x 加 1"都不会触发。代价是"根号下x的平方加y的平方"这类明显的整体开方，也会多出一个 chip，这和下面"宁可多一个 chip"的原则一致。

**一致性检查，不是核验**。模型给出的 `expected` 值来自它对输入的同一份理解：模型理解错了用户，公式和期望值会一起错，Compute Engine 比对照样通过。所以这条路径只能发现"公式没算出模型自己想要的值"这类抄写错误和明显的结构异常，不能证明 AI 理解正确。v1 就按这个降低承诺来写文案与 UI；真正的正确性核验需要独立信号，例如用不同提示让模型把生成的 LaTeX 反向描述成文字再与用户输入比对，这留到 v0.3 之后评估。Compute Engine 求不出数值时，检查直接跳过，不报"不一致"；等式、不等式、结果仍含变量的式子（如 `2x`）都属于这种情况。提示词也要求模型对这类式子填 `none`（S4）。

**歧义 UX**：采用 Wolfram|Alpha 的做法，默认取最常见解释插入，节点旁出现"按 sin(x)/x 理解 · 改为 sin(x/x)"的 chip，点一下切换到 `alternatives`。不弹对话框。`alternatives` 只放含义不同的读法，宿主据此统一 status：有 alternatives 就是 ambiguous，没有就不出 chip。模型答 ok 却给了其他读法时，按 ambiguous 处理，因为藏起一种不同的读法，代价比多出一个 chip 大。同一含义的其他写法放在 `notations`，不出 chip，以后可以放进公式的"其他写法"菜单（S4 发现 4 的决定）。

**模型选择（2026-09-26 定案）**：你实测 DeepSeek 的 flash 级模型做模糊输入转 LaTeX 效果很好，默认接入它；不做专用微调模型，不做本地离线模式。注入函数仍保持供应商无关，默认实现是一个 DeepSeek 适配器。若所用接口不提供 schema 级的受约束解码，就用它的 JSON 输出模式加提示词内嵌 schema，宿主同步门照常兜底。用非推理模式。延迟目标按用户能感知到的来定：要等完整 JSON 到齐才能插入，所以目标是完整结果 p50 < 0.8 s、p95 < 1.2 s。原先写的"首 token 0.5 秒内"主要受服务端限制，只作参考。（ai_layer Q7；S4 后修订）

**S4 实测结果（2026-09-26，详见 `docs/spikes/S4 AI 语料评测.md`）**：`deepseek-flash` 默认开着思考，必须在请求里显式传 `thinking: {type: "disabled"}`，适配器已默认这样做。不传的话，思考 token 计入 max_tokens 会导致截断（原配置 50 条里截断 2 条），temperature 被忽略，首 token 也翻倍。之后的两轮修了契约、提示词、解析、重试和宿主语义检查。另外新写了一套留出语料：只用来验证，从不用来调提示词。开发集（80 条生成加 17 条改写）三轮全过，歧义暴露 10/10，误报歧义 1/58，这一条就是上面说的根号 chip。留出集（64 条生成加 11 条改写）三轮全过，歧义暴露 17/17，误报歧义 0/41，越界 4/4，误拒 0。重试提示词 8/8，选区改写全过；模型声明的数值和 Compute Engine 的求值全部正确。完整结果 p50 0.82 s、p95 1.17 s，p50 略超 0.8 s 的目标，提示词已从约 1.1k token 增加到 2.1k token（91% 命中前缀缓存）。遗留问题：指数的作用范围还没定约定，`e to the x plus one` 以 e^{x+1} 为主解释，两种读法都在 chip 里；所有轮次里都没出现过自然发生的 KaTeX 拒绝，"带报错重问"只在构造的用例里验证过。

### D7 能力边界（R9）

原则：**宿主判定，模型辅助声明。** 模型的 `features` 只是提示；最终以 AST 清点加渲染器错误码为准。实测 KaTeX、MathJax、MathLive、Compute Engine 对 `tikzcd` 给出一致且可机读的信号。二者不一致时记日志，用于改提示词。（ai_layer Q5）

**两个概念分开**：`features` 是功能或宏包依赖（tikz-cd、physics、amscd、label），`renderBackend` 和 `editBackend` 是执行后端（katex、mathjax、tikzjax、server-tex；mathlive、source）。v0.1 里两处 `requires` 混用了这两个概念，已拆开。这样将来加新渲染器不会污染功能语义。

**能力注册表**：不是简单的"命令到层级"映射，因为能力常依赖命令加参数、所在环境、文档宏表、渲染器版本、编辑器版本。注册表是一组带条件的规则，整体带版本号；能力快照 = 注册表版本 + 各引擎版本 + 宏表版本。

```ts
interface CapabilityRule {
  feature: string;                       // 'env:tikzcd' | 'macro:\qty' | 'env:CD' | 'macro:\label' …
  when?: { args?: RegExp; inEnv?: string[]; needsMacro?: string[] };
  render: 'katex' | 'mathjax' | 'tikzjax' | 'server-tex' | 'none';
  edit: 'mathlive' | 'source' | 'none';
  status: 'supported' | 'upgrade' | 'planned' | 'unsupported' | 'strip' | 'rewrite';
  rewriteTo?: string;                    // status === 'rewrite' 时
  message?: string;                      // 边界文案的键
}
```

示例条目：

| feature | render | edit | status | 含义 |
|---|---|---|---|---|
| `\frac`、`\int`、`\lim`、`align`、`cases`、`pmatrix` … | katex | mathlive | supported | 可渲染、可结构化编辑 |
| `env:CD`（amscd 简化交换图） | katex | source | supported | KaTeX 可渲染，MathLive 不认识，只能源码编辑 |
| `\qty`、`\bra`（physics） | mathjax | source | upgrade | 升级 Tier 2 渲染，标注不可结构化编辑 |
| `env:tikzcd`、`env:tikzpicture`、`\xymatrix` | none | source | planned | 暂不支持，可后续添加（Tier 3） |
| `\SI`（siunitx） | none | source | unsupported | 暂不支持 |
| `\label`、`\tag` | katex | mathlive | strip | 静默去掉 |
| `\differentialD` | katex | mathlive | rewrite → `\mathrm{d}` | 静默改写 |

上表管的是这类命令真的出现时怎么处理，比如用户在源码模式里直接敲进来。AI 生成这一侧由提示词先做一层：physics、mhchem 的便捷命令一律改写成原生写法。化学式、化学方程式、带单位的数值都不算越界，用 `\mathrm{H_2SO_4}`、`25^{\circ}\mathrm{C}` 这样的原生写法输出，只有点名要 siunitx 时才按上表判为不支持。S4 发现，只在提示词里写一句"siunitx 单位不支持"，模型会连"25 摄氏度"、"硫酸的化学式"都判成越界。

**"同一公式不同写法可接受"的落地**：注册表只管构造是否支持，不管写法。AI 可以输出任何 KaTeX 支持的写法；判等和去重用 Compute Engine 的 canonical 哈希，绝不改写用户存下的源码。

**文案模板**（遵循 Google PAIR 的"具体说明限制 + 给替代路径 + 交还控制权"）：

- 暂不支持：「交换图（tikz-cd）目前超出本编辑器的渲染范围。这不是识别错误，原始 LaTeX 已保留。可以：① 改用简化交换图（仅水平和竖直箭头）② 保留源码，等支持后自动渲染 ③ 复制到 Overleaf」
- 已升级渲染：「已用增强渲染器（MathJax）显示；该公式暂不支持可视化编辑」
- 语义存疑：「按 sin(x)/x 理解 · 改为 sin(x/x)」

视觉规则：能力边界用中性信息色加"可后续添加"标签；AI 失败用警告色加"重试"。**能力边界不自动重试**，避免浪费调用，也避免让用户以为模型不稳定。

**文档节点只存事实**。v0.1 把 `tier`、`requires`、`fallback`、`semantic` 放进节点属性，这混淆了三类东西：用户创造的事实、当前版本注册表算出的分析结果、为性能保存的缓存。后两类进 ProseMirror 文档会造成：引擎升级后打开文档就要重算并产生事务、脏状态、同步差异甚至撤销记录；而"tier 每次加载重算"与"tier 存进节点"本身就自相矛盾。改为：

```ts
// 进文档：只有不能从别处重建的数据
interface MathNodeAttrs {
  id: string;
  latex: string;                        // 唯一真源，不带定界符
  display: 'inline' | 'block';
  annotations?: MathAnnotation[];       // R5 的批注：{ fragment, note, createdAt }
  provenance?: MathProvenance;          // { input, model, at }
}
// 文档级属性：宏表 macros

// 不进文档：插件状态，按需计算，按键缓存
interface MathAnalysis {
  features: string[];
  renderBackend: 'katex' | 'mathjax' | 'tikzjax' | 'server-tex' | 'placeholder';
  editBackend: 'mathlive' | 'source';
  issues: { kind: 'syntax' | 'unsupported' | 'renderer-gap' | 'semantic'; message: string; position?: number }[];
  semantic?: { mathjson: unknown; engineVersion: string };
}
// 缓存键 = hash(latex, display, macrosVersion, katexVersion, mathliveVersion, registryVersion)
// 渲染缓存（svg / mathml / html）用同一把键放 LRU 与 IndexedDB
```

**升级路径**：分析是按当前能力快照算出来的，Tier 3 上线后原来显示占位的 tikz-cd 节点自然变为可渲染，不需要迁移任何数据，因为真源一直是 `latex`。OOXML 的 AlternateContent 和 MathML 的 semantics/annotation 那套"源码 + 能力声明 + 回退"模式，用在**导出格式**上（D11），不用在活文档里。（formula_representation_formats Q5）

### D8 选区批注 → AI 修改（R5）

协议：**模型只返回替换片段，宿主用结构化编辑器把它放回原位**。模型在协议层面没有修改选区外内容的能力，响应 token 也更少。

S1 实测推翻了 v0.2 里"宿主拼接 before + replacement + after"的写法：MathLive 的 offset 是原子树的展平，选区落在下标或分式里时，前后两个区间序列化出来只是兄弟原子，不含外层结构，三段拼接不等于整条公式。所以替换必须由编辑器的 `replaceSelection` 执行，字符串拼接一律不做。

```ts
interface MathEditRequest {
  kind: 'edit';
  instruction: string;
  fullLatex: string;          // 整条公式，只供模型理解上下文
  selectionLatex: string;     // 选中的子表达式：adapter.getSelection().latex
  context: MathContext;
}
interface MathEditResult {
  status: 'ok' | 'unsupported' | 'unclear';
  replacementLatex: string;
  interpretation?: string;
  confidence: 'high' | 'medium' | 'low';
}
// 宿主：安全门 → 同步门校验 replacementLatex → 预览 → 接受时 editor.replaceSelection(replacementLatex)
```

流程：
1. 在编辑会话中，用户拖选公式的一部分；适配层给出选中子表达式的 LaTeX 和整条公式。MathLive 的选区会自动扩展到完整的原子（分式、上下标等）。回归用例验证了在下标内替换后外层结构保持完整。
2. 选区旁出现批注输入（一行），用户输入指令。
3. 发 `MathEditRequest`；模型返回替换片段。
4. 预览：弹层内并排显示"原渲染 / 新渲染"，源码层用字符 diff 标红绿；接受时在仍然打开的编辑会话里执行 `replaceSelection`，随后按正常路径一次提交；拒绝丢弃临时状态，可追加指令迭代。预览只在本地可见，不写入文档。（note_editor Q6）
5. 接受后把这次 AI 修改合并为一个撤销步（参照 Plate 的 `withAIBatch` 思路）。

**S4 实测（2026-09-26）**：17 条改写用例三轮全过，完整结果 p50 0.67 s。其中包括两道"只改选区"的陷阱题，模型都只返回了片段，没有重写整条公式：一道是选中 `\lim_{x\to0}` 里的 `0`、指令"改成趋于无穷"；另一道是选中 `\frac{a}{b}`、指令"分子分母对调"。指令不清时答 `unclear`，要求画交换图时答 `unsupported`。

字面保证如 D1 所述：因为已经进入结构编辑，三段都来自 MathLive 的序列化，选区外区域保证结构不变，不保证字节级拼写与原文一致。

批注的持久化：MathLive 没有公开"源码字符偏移 ↔ 模型 offset"的映射，所以批注存为 `{fragment, note}` 挂在节点上，重新高亮时用片段文本匹配；不用 `applyStyle` 上色，因为颜色命令会被序列化进 LaTeX 污染源码。v1 接受"片段文本匹配"的近似。（structural_math_editors Q2）

### D9 选中文字 → 公式（R6）

一条 Tiptap 命令：取选区纯文本，先过 D6 的意图分类（显式 LaTeX 直接转，不调 AI），否则调 `resolveMath({kind: 'convert'})`；等待期间选区替换为带旋转指示的占位节点；成功则替换为公式节点，越界则恢复原文并显示边界提示。默认快捷键沿用 Notion 的 `Cmd/Ctrl+Shift+E`，可配置。反向命令"公式转回文字"也提供，实现是删节点、插入其 LaTeX 文本。（note_editor Q5）

配合听写（R7）：用户口述一段话，其中夹着数学，全部落为文字后，只需选中数学部分按一次快捷键。这条命令是语音工作流的核心。

**已实现（2026-09-26）**：选中文字后浮出"转为公式"气泡（快捷键同上）。选中的是一整条公式时（同一段内的字面 LaTeX，或 `sin x` 这类没有叙述的短式子）整体转换，整段选中则转成块级公式；否则只转换选区里的公式描述，其余文字不动，做法与下面的一键转换相同，只是范围限于选区。早先的实现把整个选区当成一条公式交给模型，多段选区里的叙述会被吞掉，已改。没有选中时 `Cmd/Ctrl+Shift+E` 插入一个空公式并把光标放进去，`$…$` 与 `$$` 也能直接打出公式。等待 AI 期间选区若被改动，不替换。新公式在离开时作为一次插入记入撤销历史，留空离开则不留痕迹。

**一键转换整篇（`resolveMath({kind: 'scan'})`）**：把笔记里所有"用文字描述的公式"一次转成公式，普通笔记不动。协议沿用 D13 的思路：宿主把各文本块投影成带编号的线性文字（已有公式写成 `$…$`），模型只回 `{block, quote, latex}`，quote 必须逐字摘自原文；宿主按 quote 定位，定位不到、与已有公式或其他片段重叠、KaTeX 渲染不了的都丢弃并保留原文，其余在一个事务里替换，一次撤销全部恢复。一段文字整段都是公式描述时转成块级公式。长笔记按字数分批并发请求，不含任何数学迹象的段落不发送。DeepSeek flash 在 11 段混合语料上抽查两轮：14 处全部逐字定位、无误转，约 2 秒（`tiptap/scan.ts`、`ai/scan.ts`）。

### D10 源码模式（R4）

- 节点级：编辑会话内一个切换按钮，在 `<math-field>` 与一个小的 CodeMirror（或 textarea）之间切换，两者编辑同一个 `latex`；切回结构模式时跑 `validate`，报错则停留在源码模式并标出位置。
- 文档级："全部显示源码"开关，所有公式节点显示为带定界符的等宽文本，服务重度用户。
- `editBackend === 'source'` 的节点只能进源码模式，进入时显示原因标签。

**已实现的"文本模式"（2026-09-26）**：文档级开关，公式平时照常渲染；点开一个公式，它就地变成可编辑的 LaTeX 源码，下方弹窗用 KaTeX 实时预览，出错时弹窗保留上一次正确的渲染并标出位置。源码编辑器实现了与 MathLive 相同的适配接口（`source/source-editor.ts`），会话、退出、一次提交、撤销与结构化编辑共用一套。块级公式源码里回车换一行公式：不在环境里时包进 `gathered`，写入 `\\`；Shift+回车只是源码换行。

### D11 封装与导出（R8）

- 三层交付物：核心是一组 Tiptap 扩展（公式节点、AI 命令、边界反馈、导入导出），纯 JS 无框架依赖；其上是 React 绑定，learning-oj 是 React + Vite，NodeView 用 `@tiptap/react` 的 `ReactNodeViewRenderer`，这是 v0.2 MVP 的交付形态；最外面是 v0.4 的 web component（暂名 `<math-notes>`），用属性传 `resolveMath`、`capabilities`、`macros`、`value`，用事件发 `change`、`math-inserted`、`boundary-hit`，给非 React 宿主用。
- 导出：Markdown 用 `$…$` 和 `$$…$$`；不可渲染的节点按 pandoc 的做法输出 ```` ```{=latex} ```` 围栏；Anki 导出时换成 `\(…\)` 与 `\[…\]`（Anki 不把 `$` 当定界符）；HTML 导出用 MathML 加 TeX annotation，`renderBackend` 为 none 的节点写入缓存里的回退 SVG 与 `data-requires` 声明。定界符在导出时决定，不存。
- 学习系统钩子：每个公式有稳定 `id`；Compute Engine canonical 哈希作检索和去重键；`provenance` 与 `annotations` 随导出携带为侧数据。RemNote 允许选中公式局部后直接生成挖空卡片，这是"公式局部到卡片"的现成先例，D8 的选区机制可以在 v0.4 之后复用到这里。
- 宏：文档级宏表随文档保存；导出到不支持宏的目标时用 `latex-expanded` 展开。

### D12 中文、IME 与听写（R7）

- 输入框是普通 textarea，系统听写直接可用。提示词的少样本要覆盖中文口述习惯：分数分母先读（"三分之二"是 2/3）、"x 的平方"、"根号下"、三角函数用英文读法、中英混说。目前没有公开的中文口述数学数据集，只能自建一个 50 条左右的小评测集。（ai_layer Q8）
- 数学模式里出现中文时，KaTeX 的 `strict` 回调会报 `unicodeTextInMathMode`，流水线自动包进 `\text{}`。
- **IME 测试是一个矩阵，不是一次拼音实测**。#3058 表明问题不限于组字阶段，且注音的 bug 无法用拼音验证。矩阵至少覆盖：

| 维度 | 取值 |
|---|---|
| 输入法 | macOS 拼音（你的主平台，最优先）、Windows 微软拼音、Windows 微软注音 |
| 位置 | 公式前中文输入、公式后中文输入、组字中点击公式、`move-out` 后立即组字 |
| 程序化插入 | 组字中 `insert()`、组字刚结束 `insert()`、`insert()` 后的第一次物理按键 |

- 自动化的边界：真实 IME 无法被 Playwright 驱动，程序化输入会绕过 IME（#3058 的报告者也这么说）。可以用 CDP 的 composition 事件模拟覆盖一部分组合，但每次 MathLive 升级仍需要按矩阵人工过一遍，矩阵本身写成清单。

### D13 AI 文档投影

ProseMirror 的 JSON 是编辑器内部结构，不是 AI 协议。给模型读的是一份专门的线性投影：人类可读的类 Markdown 文本，段落和公式带稳定 ID，另附位置映射。模型读线性文本，回写时按节点 ID 定位，宿主再转成结构化事务。

```
[h1:n01] 泰勒展开
[p:n12] 考虑函数 ⟦m:m31⟧$e^x$⟦/m⟧ 在 $x=0$ 附近……
[m:m32 block]
e^x = 1 + x + \frac{x^2}{2!} + \cdots
[/m]
```

```ts
interface AIDocumentProjection {
  text: string;
  spans: { id: string; kind: 'paragraph' | 'heading' | 'math-inline' | 'math-block'; from: number; to: number }[];
}
// 模型回写形态之一：{ target: 'm32', kind: 'math-error', comment: '…' }
// 形态之二：{ op: 'replace_text', node: 'n12', from: 13, to: 27, replacement: '…' }
```

用途：
- D6 里 `surroundingText` 与 `notation` 从这份投影截取，而不是从 DOM 或 PM JSON 里抠。
- 将来的"检查整篇笔记的数学错误与逻辑跳步"（R8 之后的功能）：模型输出针对节点的评论或补丁，而不是返回整篇改稿，避免顺手改掉没让它改的地方。
- 与 Markdown 导出共用序列化器，只是多了 ID 标记与 span 映射。

### D14 不可信 LaTeX 的安全模型

AI 输出、用户粘贴、将来同步而来的 LaTeX 都是**不可信的程序输入**，不只是不可信的 HTML。0.110.0 修掉的 XSS 只是其中一类；宏炸弹、超深嵌套、超大尺寸、外链命令、病态表达式都要有边界。在同步门最前面放一道安全门：

```
原始 LaTeX
 → 源码长度上限（行内与块级分别设，数值在 S5 定）
 → 宏展开上限：KaTeX maxExpand（默认 1000，按需下调）；MathJax maxMacros、maxBuffer
 → 尺寸上限：KaTeX maxSize
 → 信任策略：KaTeX trust: false，拒绝 \href、\url、\includegraphics、\htmlData 一类命令；MathJax 加载 ui/safe
 → AST 深度与节点数上限（unified-latex 清点时顺带统计）
 → 重活全部进 Web Worker 并带超时与内存预算：Compute Engine evaluate、MathJax、TikZJax
 → 服务端真 TeX 若上线：容器隔离、禁 shell-escape、时限与内存限制（Anki 官方也警告本地 LaTeX 能读写文件）
```

触发上限时的处理与能力边界同一套 UI：保留源码、显示原因、不自动重试。

## 4. 关键流程

**A. 输入框到公式**：输入 → 意图分类 → 直接插入或 AI → 安全门 → 同步门 → 插入到光标处（行内或块级由输入框旁的开关或输入中的换行决定）→ 输入框清空 → 异步检查补充装饰。整个过程用户只看到公式出现，没有对话气泡。

**B. 点击到编辑**：点击渲染态公式 → 按 D3 的档位挂载 `<math-field>` → 光标落到点击的子元素 → 编辑 → Esc、失焦或 `move-out` → 校验 → 一次提交 → 卸载字段，恢复静态渲染。

**C. 选区批注到修改**：见 D8。

**D. 越界处理**：AI 或流水线判定 `unsupported` → 不插入公式 → 原文保留在输入框或选区 → 中性色提示，列替代路径 → 用户可选"保留源码占位"，得到一个 `renderBackend === 'placeholder'` 的节点，将来自动升级。

**E. 整篇审阅（后续）**：D13 投影 → 模型返回按节点 ID 的评论或补丁 → 宿主渲染为侧边评论或可接受的建议。
