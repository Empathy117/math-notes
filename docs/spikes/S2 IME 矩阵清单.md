# S2：输入法矩阵清单（人工）

背景：MathLive #3058 表明程序化 `insert()` 之后的第一次物理按键会被注音输入法的组字逻辑吞掉，且在字母数字模式下同样复现；报告者指出自动化测试无法重现，因为程序化输入绕过了输入法。所以这份矩阵按人工执行，每次 MathLive 或 Tiptap 升级后过一遍，结果记在文末。

启动：`pnpm dev`，打开 playground，行内模式先用"真就地 inplace"。

## 矩阵

| # | 输入法 | 场景 | 步骤 | 期望 |
|---|---|---|---|---|
| 1 | macOS 拼音 | 公式前输入中文 | 光标放在行内公式前，输入"极限" | 两个字都进入正文，公式不动 |
| 2 | macOS 拼音 | 公式后输入中文 | 光标放在行内公式后，输入"成立" | 同上 |
| 3 | macOS 拼音 | 组字中点击公式 | 输入拼音 `jixian` 不上屏，直接点公式 | 拼音被提交或丢弃都可以，但不能进入公式；字段正常打开 |
| 4 | macOS 拼音 | 退出公式后立刻组字 | 在字段末尾按 → 退出，马上输入 `chengli` 并选字 | 汉字进入正文的正确位置 |
| 5 | macOS 拼音 | 字段内切换到中文输入法后按键 | 字段内切到拼音，输入 `x` | MathLive 收到 x（拼音状态下的字母应直接进字段或形成组字后被丢弃，不能出现半个字符） |
| 6 | macOS 拼音 | `insert()` 后第一次物理按键 | 在浏览器控制台对打开的字段执行 `mf.insert('\\frac{\\placeholder{}}{\\placeholder{}}', {selectionMode:'placeholder'})`，然后按数字 3 | 得到 `\frac{3}{…}`，不是 `3` 覆盖整个分式 |
| 7 | Windows 微软拼音 | 同 1 到 6 | | |
| 8 | Windows 微软注音 | 同 1 到 6，重点是 6 | | #3058 的原始场景 |
| 9 | 任意 | 输入框（底部 textarea）里听写中文后回车 | 用系统听写说"x 的平方" | 文本完整进入输入框，回车走 AI |

## 自动化边界

Playwright 不能驱动真实输入法。可以用 CDP 的 `Input.imeSetComposition` 模拟组字事件覆盖第 1、2、4 项的一部分，但第 3、5、6、8 项只能人工执行。
