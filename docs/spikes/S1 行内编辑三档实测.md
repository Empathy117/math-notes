## 过程中发现并修复的问题

1. **MathLive 挂载前的 setter 会抛错**。`menuItems`、`macros`、`inlineShortcuts`、`keybindings` 在元素连接到 DOM 前访问会抛 "Mathfield not mounted"。适配层改为在 `mount` 事件里设置。
2. **退出时多走一格**。`move-out` 在字段处理 keydown 的过程中同步触发，我们据此结束会话并把宿主光标放到节点后，但同一个 keydown 随后继续传到 ProseMirror，又把光标向右移了一格。修复：退出时对该 keydown `preventDefault` + `stopPropagation`，并让 `stopEvent` 吞掉它。
3. **段首公式拖选失效**。根因：ProseMirror 给没有 `contentDOM` 的 NodeView 整体设置 `contenteditable=false`，浏览器在段首找不到可落锚点的位置。解法：外层 span `contenteditable=true`，静态内核 `contenteditable=false`，两侧各放一个 1px、`draggable=false` 的 `<img>` 作缓冲。`ignoreMutation` 返回 true 保证 ProseMirror 不读外层的任何变动，选区同步会把落进外层的光标立刻移出。这就是论坛里没有公开代码的那个方案。
4. **`<img>` 默认可拖拽**。缓冲 img 不设 `draggable=false` 时，从它上面按下鼠标会触发原生图片拖拽而不是文本选区。
5. **宿主 `contenteditable=false` 会让 MathLive 拒收键盘输入**。无论是显式设置还是从祖先继承，表现都是 `hasFocus()` 为 true 但 value 不变。块级节点起初拿不到输入就是这个原因；第 3 条的结构顺带解决了它。设计稿里"字段挂在 contenteditable=false 的节点内"的假设不成立，已改。
6. **overlay 占位宽度**。占位用 `min-width` 时，MathLive 比 KaTeX 更紧凑（同一公式 90px 对 136px），正文不会跟着收；改用 `width` 后又因内容换行把段落撑高。最终：`width` + `white-space: nowrap` + `overflow: hidden`。

7. **MathLive 的 `focus()` 可能不真正夺取 DOM 焦点**。无头 Chromium 里 `mf.focus()` 后 `document.activeElement` 仍是 body，但 `mf.hasFocus()` 返回 true（内部标志），键盘事件全部落空。适配层改为：`focus()` 之后若宿主元素不是 activeElement，直接聚焦 shadow root 里的 `.ML__keyboard-sink`；`hasFocus()` 改用 `document.activeElement === host` 判断。桌面浏览器里没复现，但这是零成本的兜底。
8. **在 `move-out` 里同步销毁字段会让 MathLive 报错**。`move-out` 是在 MathLive 处理 keydown 的过程中同步派发的，我们在回调里立刻 `remove()` 字段，MathLive 随后继续处理这次按键，在 announcer 里访问已销毁的元素抛 TypeError（Vite 会把它当作未处理错误上报）。修复：退出时同步消费按键、提交事务、移动宿主光标，字段的销毁推迟到微任务。
9. **序列化区间不能拼接**。`getValue(0, s) + getValue(s, e) + getValue(e, last)` 不等于整条公式：选区在下标里时，前后两段只是被展平的兄弟原子，不含外层结构（`\lim_{…}` 的壳丢了）。设计稿 D8 原来的"before + replacement + after 由宿主拼接"协议因此不成立，改为：模型拿整条公式和选中片段，只返回替换片段，宿主用结构化编辑器的 `replaceSelection` 放回原位。回归用例验证了在下标里替换后外层结构保持完整。
10. **inline-block 加 `overflow: hidden` 会改基线**。overlay 占位一旦设了 `overflow: hidden`，基线变成盒子底边，整行高 +9.75px；去掉它只保留 `white-space: nowrap` 即可（内容本来就是 `visibility: hidden`）。
11. **Shift+方向键紧贴公式时原生扩选会卡住**。按键连续到达时，浏览器把选区焦点落在节点缓冲位上就不再前进。改为由键盘映射接管：head 紧邻公式时，跨过整个节点或迈出第一个字符，之后交回原生。

## 无头浏览器与真实浏览器的差异

回归套件跑在 Playwright 的无头 Chromium 上，有三处行为与桌面浏览器不同，测试里做了对应处理：`view.focus()` 在没有真实用户交互前不生效（先点击再设选区）；连续按键快于 ProseMirror 的选区同步（按键之间加 40ms）；MathLive 的 `focus()` 不夺焦点（第 7 条的适配层兜底）。这些差异本身也是回归价值的一部分。

## 观察到的引擎差异

- **`\lim` 的 limits 位置**：行内样式下 KaTeX 放在右下，MathLive 放在正下方（`\sum` 两者一致，`\lim\nolimits` 可绕过）。这是档 1 行高 +5.5px 的全部来源。
- **序列化漂移比预期激进**：任何一次编辑后 MathLive 重新序列化整条公式并去掉全部空格：`\lim_{x \to 0} \frac{\sin x}{x} = 1` 编辑末尾后变成 `\lim_{x\to0}\frac{\sin x}{x}=1+2`。设计稿 D1 写的"结构编辑后不保证未选中区域字节不变"是准确的，"未改动子树回吐 verbatim"在实测里没有体现。
- **宽度差**：同一公式 KaTeX 静态 136px、MathLive 90px，进入编辑时正文回流是三档共有的现象，popover 除外。

## 后续修复（2026-09-26，S1 之后）

S1 记下的引擎差异和几处输入问题已经修掉，回归见 `apps/playground/e2e/editing.spec.ts`，S1 的布局门槛收紧为三档都不超过 0.5px。

1. **`\lim` 行高 +5.5px 已消除**。根因不止 limits：MathLive 0.110.0 把 `\lim \max \min \det \liminf \limsup \operatorname* \mathop` 写死为"上下限在正下方"，把 `\sup \inf \gcd \Pr` 写死为"在右侧"，而 TeX 和 KaTeX 对它们都是 `\displaylimits`（行内在右侧、块级在下方）。适配层在载入字段时给这些算符补一个 `\displaylimits`，读回时去掉（`adapter/latex-shims.ts`），两个方向在 TeX 里都是空操作；`lim` 等内联快捷方式也改成带 `\displaylimits` 的版本。另外两处尺寸差：KaTeX 的 `.katex` 是 1.21em、行高 1.2，字段原来是 1em、继承正文的 1.8 行高，所以打开后公式变小、所在行变高。字段改成同样的 1.21em 与行高 1.2 后，宽度 136.0px 对静态 136.2px（原来 90 对 136），行高不变。
2. **块级公式编辑态与静态渲染一致**：字段内容居中（`::part(content)`），块的上下间距放在节点上而不是 `.katex-display` 上，打开时高度只差 1px、顶部不偏移（原来 -4.7px / -5.0px）。
3. **`dx` 打出来的公式提交后渲染失败**：MathLive 的 `dx` 快捷方式生成 `\differentialD`，KaTeX 不认识。读回时改写为 `\mathrm{d}`（`\exponentialE`、`\imaginaryI` 同理）。
4. **空格**：MathLive 的空格是"跳出当前分支"，在顶层什么也不做。现在指数、分式、根号里仍是跳出；顶层、多行环境的某一行、`\left…\right` 里插入 `\;`。TeX 已经留了间距的地方（`=`、`+` 之后，`\sin` 之后）不再插；空格后紧跟运算符时收回这个空格，所以习惯性打的 `x = 1` 仍是 `x=1`。判断光标在哪一层用了 MathLive 的内部 model，只在适配层里。
5. **回车**：块级公式里回车换行。MathLive 的 `addRowAfter` 在顶层会把整条公式包进它自己的 `lines` 根，序列化成 KaTeX 不认识、且左对齐的 `\displaylines`；适配层当场换成 `gathered`，光标位置不变（两者的 offset 恰好差 1，实测）。已在多行环境里就直接加一行。行内公式里回车表示完成。
6. **退出与提交**：只有用户改过的值才写回，打开再关上的公式保留原字节（D1）；MathLive 的 `input` 事件是异步派发的，"打字后立刻 Esc"要靠和挂载时的值比较来发现改动。清空的公式离开时删除。块级公式在文末或两个块之间时，离开会补一个空段落，保证 → 之后总能继续写文字。
